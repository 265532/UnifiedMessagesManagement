# 钉钉接入：从装客户端到跑通第一个闭环

钉钉比飞书难缠的地方在于：网页版已经停服，所有配置都得在桌面客户端里点。个人账号还有一层限制——建不了群。这份文档把这两件事怎么绕过去写清楚，照着做大概 20 分钟。

结论先放着：**两个方向都真实跑通了**。手机发一句系统能收到，网页点回复手机上能收到，全程不需要公网地址。中间踩过的坑在第 10 节。

## 0. 先确认三件事

- 有一个钉钉账号。个人账号能登录，但没加入任何组织的话，建群会失败，见第 2 节。
- 项目在本机能跑起来（`python app.py`，能看到 8000 端口）。
- 装好钉钉桌面客户端。`https://im.dingtalk.com` 会跳到「系统维护中，请前往钉钉官网下载对应版本客户端」，网页版已经不用了。

客户端下载装完登录，向导页会推「创建企业/组织/团队」。个人演示不用建组织，跳过就行。

## 1. 两条路，最后都走了

钉钉发消息有两条路。

**群自定义机器人**：加进任何一个群，拿到一个 Webhook 地址，往上面 POST 一个 json，群里立刻出现消息。不需要 app_key，不需要审核，也不需要公网地址。这条路最快，项目最早走的就是它。

**企业内部应用**：要建应用、开机器人能力、发布上线，再用 ClientID/Secret 换 token 调接口。麻烦得多，但它是唯一能**收**消息的路——群机器人是单向的，发得出去收不回来。

两条最后都接上了，各管一个方向：

| 方向 | 通道 | 代码 |
|---|---|---|
| 发到群 | 群自定义机器人 Webhook | `_send_by_webhook()` |
| 发到单聊 | 企业内部应用机器人单聊 | `_send_by_robot_single()` |
| 收消息 | 企业内部应用 + Stream 长连接 | `adapters/dingtalk_stream.py` |

原先以为自建应用对个人账号走不通（要组织管理员、要审核），实际能走：建组织在钉钉客户端「通讯录 → 创建团队」几步就完事，企业内部应用发布选「免审发布」即可。真正卡住的不是权限，是几个必须单独点一次的按钮，见第 10 节。

## 2. 找一个能用的群（个人账号的坎）

正常做法是建个群，把机器人加进去。但个人账号这一步会卡住：

| 试过的路径 | 结果 |
|---|---|
| 发起群聊 → 内部群 | 通讯录只列自己（没有组织） |
| 发起群聊 → 外部群 | 同样只列自己，得用搜索框才搜得到好友 |
| 搜到好友、勾上、填群名、点「确定」 | 弹窗关了，但跳到和好友的单聊，群列表里没有新群 |

「确定」按钮会变蓝，看着像成功了，实际上群没建出来。通讯录 → 我的群组里还是只有原来那一个。换个好友组合、换内部群外部群都一样。

**所以演示用系统自带的群。** 登录后「消息」列表里有一个「欢迎试用钉钉群（团队）」，一人群，自己是群主。这个群是钉钉给的，可以正常加机器人。

要一个干净的演示群，得先把组织建起来或者拉到第二个成员，这两件事本项目都没做——`.env` 里的 Webhook 指向的是这个系统群。文档里如实写清楚，别让评委以为是自己建的群。

## 3. 加自定义机器人

在「欢迎试用钉钉群」里操作：

1. 右上角齿轮 → 群设置。
2. 往下滚，找到 **「机器人」** 这一栏（副标题「机器人具备丰富的技能，让沟通协同更智能高效」）。
3. 点进去是机器人管理面板，里面已经有一个「小钉」。点顶部 **「添加机器人」**。
4. 列表里选 **「自定义（通过 Webhook 接入自定义服务）」**，进机器人详情页点「添加」。
5. 配置页从上到下：机器人名字（改成「统一消息管理」）、添加到的群组（默认就是当前群）、协议勾选框、安全设置区。

配置页的两点注意：

- **「完成」按钮在左，「设置说明」在右，两个挨着。** 点到右边会打开 open.dingtalk.com 的文档页，看起来像点错了没反应。
- 安全设置那一行要先向下滚动才看得全，三个选项是竖排的：自定义关键词 / 加签 / IP地址(段)。鼠标停在「安全设置」的问号上会弹 tooltip 挡住下面的复选框，把鼠标移开再看。

## 4. 选「加签」

钉钉**强制至少配一项**安全设置，不配点不了完成。三选一，本项目用加签：

| 选项 | 意味着什么 | 为什么不选 |
|---|---|---|
| 自定义关键词 | 消息内容必须包含指定关键词，否则发不出去 | 卡消息内容，回复里得硬塞关键词，很别扭 |
| 加签 | 每次请求带 `timestamp` 和 `sign`，密钥参与 HMAC | 选这个，代码已经实现 |
| IP地址(段) | 只接受指定 IP 的请求 | 本机 IP 会变，换网就得改配置 |

勾上「加签」后，下方会展开密钥输入框和「重置」「复制」两个按钮。密钥 `SEC` 开头、67 个字符，点「复制」拿全。

**这个密钥等同于群里的发言权限，只能放 `.env`，不要写进文档、截图或仓库。**

点「完成」，成功页会显示：

```
Webhook: https://oapi.dingtalk.com/robot/send?access_t...
```

点右边「复制」拿到完整地址。地址里的 `access_token` 同样是凭证，一泄露别人就能往这个群里发消息。

## 5. 写进 `.env` 并重启

```
# 群自定义机器人：发到群，安全设置用「加签」
DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxx
DINGTALK_WEBHOOK_SECRET=SECxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# 企业内部应用：收消息、发单聊都靠这几个
DINGTALK_APP_KEY=dingw1ozw0lt9nqe0u00
DINGTALK_APP_SECRET=（64 位，只写在 .env 里，不要提交）
# 网页上点回复时发给谁。填通讯录里的真实 userId，不是回调里的加密 senderId
DINGTALK_DEFAULT_USER_ID=023519171132751217
UMM_DINGTALK_STREAM=1
```

`UMM_MODE` 不用改成 `real`。代码的判断顺序是「Webhook 有值就真发」，排在 mock 分支前面，所以演示形态是「接收模拟、发送真实」。

改完必须重启进程——`config.py` 只在启动时读一次 `.env`。

## 6. 代码里怎么走的

`config.py` 的 `DINGTALK` 字典里，跟这件事相关的几项：`webhook_url`、`webhook_secret`、`app_key`、`app_secret`、`default_user_id`，另有一个给新版 API 用的 `api_base_url`。

`adapters/dingtalk.py` 的 `send()` 按这个顺序判断：

1. `default_user_id` 有值且是文本 → `_send_by_robot_single()`，机器人单聊发到这个人。成功就直接返回。
2. 第 1 步失败（或没配收件人）且 `webhook_url` 有值 → `_send_by_webhook()`，先过一遍 `_sign_url()` 再 POST。
3. 单聊试过但确实失败、又没有 Webhook 兜底 → 把单聊的真实错误直接报出去。这里不退回工作通知：收件人不是同一个人，退回去没有意义，只会把错误信息盖住。
4. 都没有且 `MODE=mock` → 假装发送成功。
5. 都没有且 `MODE=real` → 拿 `access_token` 调工作通知接口（没联调过）。

签名这一段在 `_sign_url()` 里：

```python
timestamp = str(round(time.time() * 1000))
string_to_sign = f"{timestamp}\n{secret}"
digest = hmac.new(secret.encode(), string_to_sign.encode(), hashlib.sha256).digest()
sign = urllib.parse.quote_plus(base64.b64encode(digest))
url = f"{url}&timestamp={timestamp}&sign={sign}"
```

`sign` 要 URL 编码，`+` 和 `/` 不编码会被服务端当成参数分隔符，签名直接失效。密钥没配就跳过签名，原地址直接发。

返回值判断：`errcode == 0` 算成功。群机器人通道没有消息 ID 返回，所以 `platform_msg_id` 是空串，页面上仍会标「已发送」——判据是接口返回，不是消息 ID。

## 7. 验证闭环

**第一轮，通道自测。** 直接调适配器，跳过页面和状态机：

```bash
python -c "from adapters.dingtalk import DingTalkAdapter; print(DingTalkAdapter().send('t','text',{'text':'连通测试'}))"
```

返回 `{'ok': True, 'platform_msg_id': '', 'error': ''}`，钉钉群里几秒内出现这条消息，通道就通了。

**第二轮，端到端。** 打开 http://127.0.0.1:8000 ，找一条平台标着「钉钉」的消息，依次点「已展示」→「已处理」，写一句回复点「发送回复」。状态变成「已发送」，右侧九步流水线走到最后一格，钉钉群里出现对应的业务回复。

两轮都在本机跑过，2026-11-15 的实际结果：

| 检查项 | 结果 |
|---|---|
| 配置读取 | `webhook_ok=True`，`secret_len=67` |
| 通道自测 | `errcode=0`，群里出现「钉钉 Webhook 通道连通测试」 |
| 端到端 | 消息推到 `replied`，群里出现「【统一消息管理】您的问题已收到，正在跟进处理」 |
| 机器人管理面板 | 显示「统一消息管理（由姚锋 添加）」 |

截图建议截三张：机器人管理面板里的「统一消息管理」、群里收到的测试消息、本项目页面里那条钉钉消息处于「已发送」。

## 8. 出问题怎么查

| 现象 | 最可能的原因 | 怎么确认 |
|---|---|---|
| 点「完成」没反应 | 没配安全设置，或点到了右边的「设置说明」 | 先向下滚动确认三个选项里勾了一个；「完成」在左 |
| 返回 `310000` 之类错误码 | 安全设置没对 | 加签要配密钥；关键词要对得上；IP 段要匹配出口 IP |
| 返回签名相关错误 | 密钥填错、或服务器时间偏移太大 | 密钥 `SEC` 开头 67 字符；时间戳是毫秒级 |
| 群里没消息但返回 `errcode=0` | 机器人加错了群 | 机器人管理面板里能看到它挂在哪个群 |
| 建群点「确定」后跳到单聊 | 个人账号建群失败 | 见第 2 节，改用系统群 |
| 发文件报错 | 群机器人只支持文本 | `_send_by_webhook()` 对非 text 直接返回明确错误 |

## 9. 这条路的边界

- **群机器人 Webhook 只能发，不能收。** 它是个单向推送地址，钉钉不会通过它把群消息推回来。收消息另有一条通道，见第 10 节。
- **只能发文本。** 富文本、Markdown、卡片、文件都不支持。要发文件得先上传素材拿 `media_id`，那条路依赖自建应用。
- **回调签名已实现，但没跟真平台联调。** `verify()` 现在按钉钉的算法校验：`sign = base64(HMAC-SHA256(app_secret, timestamp))`，用常数时间比较防时序攻击，另外卡一小时的时间偏差防重放；`app_secret` 没配就一律拒绝。本机没有公网 https 地址，这套校验只在单元测试里验证过（正确签名放行、篡改签名拒绝、过期时间戳拒绝），还没接过真实回调。
- **演示群是系统群。** Webhook 指向「欢迎试用钉钉群」，一人群。想换成自己的群，得先解决第 2 节那两件事，然后去新群里重新加一个机器人、换掉 `.env` 里的两项。

## 10. 接收方向：长连接（Stream 模式）

群机器人 Webhook 是单向的，发得出去收不回来。要收真实消息，原本只有一条路：
自建应用 + 事件订阅 + 公网 https 回调地址。本机没有公网，这条一直走不通。

钉钉另有一个 Stream 模式，把方向反过来：程序主动去连钉钉网关，保持一条 WebSocket，
平台把消息从这条连接上推下来。不需要公网 IP，不用开端口，也不用备案。

代码在 `adapters/dingtalk_stream.py`，默认关着，开了才会去连。

### 打开之前要准备什么

1. 钉钉开放平台建一个**企业内部应用**（不是群机器人）。拿到 `ClientID` 和 `ClientSecret`，
   填到 `.env` 的 `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET`。这两个值和
   `DINGTALK_WEBHOOK_URL` 完全不是一回事，别混。
2. 这个应用要开**机器人**能力，消息接收方式选 **Stream 模式**，不要选 HTTP 回调。
3. 装依赖：`pip install dingtalk-stream`（已写进 `requirements.txt`）。
4. `.env` 里把开关打开：

   ```
   UMM_DINGTALK_STREAM=1
   ```

5. 重启 `app.py`。启动日志里会多一行 `[dingtalk-stream] 正在连接钉钉网关 ...`。

### 怎么确认它活着

```bash
curl http://127.0.0.1:8000/healthz
```

`dingtalk_stream` 那一截：

| 字段 | 含义 |
|---|---|
| `enabled` | 开关开没开 |
| `running` | 长连接当前连没连上 |
| `missing` | 缺什么（凭证 / 依赖），空字符串表示齐了 |
| `last_error` | 上次断线或建连失败的原因 |
| `last_message_at` | 最近一条真实消息到达的时间 |
| `received_count` | 这次启动以来收了几条 |

`running=false` 且 `missing` 有内容，就是凭证或依赖没到位，`missing` 会直接写缺哪个变量。

### 消息进来之后走哪

两条入口最后都进 `service.receive()`：

```
/webhook/dingtalk   → trusted=False  → 校验 timestamp + sign
Stream 长连接        → trusted=True   → 靠建连时 clientSecret 换 ticket 的那次认证
```

长连接里没有 HTTP 那套 header，硬验签名会把所有消息拒掉；身份在建连那次就已经验过，
所以这条分支跳过 HTTP 验签，但解析、格式校验、去重、入库、推前端、状态流转
全部是同一套代码，没有第二份实现。

钉钉推下来的 `msgId` 直接当幂等键，断线重连把同一条消息推两次会被丢掉。

### 目前到哪一步了

已经跑通。2026-11-17 晚上在手机钉钉的机器人单聊里发了一句，`received_count` 从 0 变 1，
网页列表顶上出现「姚锋 / 姚锋 / [赞][赞][赞]」，右栏流水线一路走到「实时推送」。
截图和接口原文在 `验证记录.md` 第 4 节。

上线过程里有三件事容易漏，漏一件都不通：

| 环节 | 漏了会怎样 |
|---|---|
| 企业内部应用走完「版本管理与发布」，状态变成「已上线」 | 手机端搜不到这个机器人 |
| 机器人配置页底部那个独立的「发布」按钮 | 组织成员在会话列表、群成员里都看不到它 |
| 发消息时单聊机器人，或者在群里 @ 机器人 | 群里的普通消息不触发回调，网关一直静默 |

第三条最费时间。日志干净不代表链路坏了——长连接建成功是不打日志的，只有 topic 不匹配才会 warning。
判断连接活着要用 `Get-NetTCPConnection -OwningProcess <pid> -State Established`，
能看到一条到 `39.99.x.x:443` 的连接就说明连上了。

### 回复怎么回到原会话

Stream 收到的消息里带 `sessionWebhook`（约一小时有效），直接 POST 它就能回在原会话。
但一小时之后、或者服务重启之后那个地址就失效了，长期运行不能只靠它。

现在走机器人单聊接口，按人发，不看会话：

```
POST https://api.dingtalk.com/v1.0/robot/oToMessages/batchSend
x-acs-dingtalk-access-token: <新版 access_token>

{"robotCode": "<appKey>", "userIds": ["<userId>"], "msgKey": "sampleText",
 "msgParam": "{\"content\": \"回复内容\"}"}
```

两个注意点：

- **`robotCode` 就是 ClientID（AppKey）**，不是另一样东西。
- **`userIds` 要用通讯录里的真实 userId**，不能拿回调里的 `senderId`。那个字段是加密串
  （`$:LWCP_v1:$...`），传进去只会收到「无效人员」。真实 userId 形如 `023519171132751217`，
  在开发者后台开「通讯录个人信息 / 部门信息 / 部门成员」三个读权限（都标着无需审批），
  再调 `/topapi/v2/user/list` 查出来，填进 `.env` 的 `DINGTALK_DEFAULT_USER_ID`。

新版 token 和旧版不通用：`api.dingtalk.com` 用 `POST /v1.0/oauth2/accessToken` 换，
`oapi.dingtalk.com` 用 `GET /gettoken` 换，两套各存一份缓存，混用会 401。

## 还没做的部分

- **群里 @ 机器人没验过。** 代码路径和单聊完全一样（同一个 topic、同一套解析），
  但个人账号建不了群，没群可 @。等有群了加进去 @ 一下就能确认。
- 自建应用的工作通知接口（`asyncsend_v2`）代码在、配置空着。机器人单聊已经跑通，
  这条留着当备选。
- `sessionWebhook` 那条「回在原会话」的路没用。现在按人发单聊，回复落在和机器人的会话里，
  不会回到原来的群。要做真正的原路返回，得把 `sessionWebhook` 存下来并处理失效重取。
