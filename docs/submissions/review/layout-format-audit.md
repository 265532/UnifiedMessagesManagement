## 0. 检查方法与证据口径

| 方法 | 内容 |
| --- | --- |
| OOXML 静态解析 | `word/document.xml`、`styles.xml`、`footer1.xml`、`numbering.xml`、`document.xml.rels`、`word/media/*`、`docProps/*`；提取段落属性、标题层级、分节、域、表格几何、图片 `wp:extent` 与锚点 |
| 图片比对 | 对嵌入图片做 SHA-256 与 `docs/submissions/assets/**` 资源哈希匹配，确定每张图对应的源图；再逐张目视核对图内文字、节点、遮挡与留白 |
| 分页推算 | 按 A4 版心 15.8 × 24.62 cm、正文宋体小四 12pt、1.5 倍行距、图片显示尺寸、表格列宽与行高，逐段累加估算页边界 |

证据标记：**【实】**＝文件内可直接复核的结构证据；**【图】**＝目视核对图片得到；**【推】**＝分页推算或原因推断，须人工在 Word/WPS 复核。

**页码说明（重要）**：7 份文档 `docProps/app.xml` 只有 `Application=Tencent office`，**没有 `Pages`**；`document.xml` 中 `lastRenderedPageBreak` 为 0；本机 Word/WPS COM 实例化被安全策略拦截，无法渲染真实页面。因此报告中的 `pN` 是**推算页码**，`段 N` 是 `document.xml` 中自上而下的段落序号（精确、可复核）。**精确页码必须人工在 Word/WPS 打开或导出 PDF 后实测**，见第 4 节。

**明确未发现的问题**（避免误判）：17 张插图全部为 `wp:inline`，显示宽高比与源图原生宽高比偏差均为 **0%**，无拉伸/压缩变形；文档内无浮动图片、文本框、VML 形状，因此**不存在 Word 层面的对象互相遮挡**；所有插图均位于正确章节，未发现图片放错章节。已发现的遮挡全部来自**源 PNG 图片内部**。

关键量化证据：

- **73 条目录项**（8/12/18/15/9/5/6）的 `PAGEREF` 域缓存结果**全部是 `1`**，且 `fldLock=0 dirty=0`，打开文档不会自动刷新。

- 7 份 `footer1.xml` 的 `PAGE` 域结果使用非法字体名 `var(--ff-body)`，每份 4 处。

## 3. 修复计划（按优先级分批）

> 全程遵守「暂不直接修改文档」：以下为**待用户批准后执行**的操作方案，本次未落地任何改动。每批完成后再进入下一批，避免分页变化导致页码复核反复。

### 批次 A — P1 域、页码与编号（优先级最高，先做）

- **修复方式**：在 Word/WPS 中「更新域 / 更新目录」刷新 `TOC` 与 `PAGEREF`；取消第 3 节 `pgNumType start=1`（改为续前节），或把封面/目录单独设为不显示页码、正文从 1 开始并保证全篇唯一；`03` 统一表编号；`可行性分析` 去掉字面序号或去掉自动编号。
- **操作步骤**
  1. 关闭 4 个残留锁文件对应的编辑器实例，确认 `release/` 无 `~$*` 文件（F19）。
