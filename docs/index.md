# 🧠 Super Agent 编排总体架构
## 1. 角色分工
| 角色 | 职责 |
|---|---|
| **Super Agent** | 任务分解与派发、依赖编排、质量门（Gate）评审、集成决策、风险监控、向上汇报 |
| **RA-Agent** | 需求分析师：用户旅程、需求清单、可行性分析 |
| **Arch-Agent** | 架构师：架构设计、消息Schema、状态机、数据库、API契约 |
| **Dev-Connector** | 平台连接器开发（飞书/钉钉/企微 Adapter） |
| **Dev-Core** | 消息核心服务（总线/转换/去重/路由/状态机） |
| **Dev-FE** | Web统一入口前端 |
| **QA-Agent** | 单元/异常/端到端测试 |
| **DevOps-Agent** | Docker镜像、部署演练、部署文档 |
## 2. 编排原则
- **契约先行**：Schema / API 定义冻结后，前端与连接器才能并行开发
- **每阶段设质量门**：Sub Agent 交付物未通过 DoD 验收，不得进入下一阶段
- **里程碑对齐比赛节点**：G4=初赛(11/20)、G6=决赛(12/20)，硬截止前预留缓冲
- **人工任务标注** 🔴：账号申请等必须由真人执行，Sub Agent 只产出指引与检查清单

# 🔄 Super Agent 监控机制
**1. Sub Agent 回报格式（每任务卡完成后必填）**
```
任务ID：IM-03 | 状态：✅完成 / ⚠️受阻 / ❌延期
交付物链接：...
DoD自检：逐条勾选
阻塞/风险：...（含需要的决策）
```
**2. 监控指标**：里程碑达成率、DoD一次通过率、阻塞项解决时长、CI构建状态、距硬截止天数。
**3. 关键依赖链与并行策略**：
```
G2契约冻结 ──┬── IM-03飞书 ── IM-04钉钉 ──┐
             ├── IM-05前端（并行）──────────┼── IM-06状态回流 ── QA ── G4
             └── IM-01脚手架 ── IM-02核心 ──┘
```
**4. 风险升级规则**：任一里程碑延期超1天 → Super Agent 介入决策（砍Could级需求保Must；加分项降级）。
